## 🔥 高優先級功能 - 分離遊戲本體與 DLC

### 功能概述
**背景：** 
- 當前搜索範圍：所有產品 (~12,000 個)
  - 包含：遊戲本體、DLC、季票、道具包、虛擬貨幣等
  - 統計時間：30-60 分鐘（全量掃描）
  
**計畫方案：**
- 只統計**遊戲本體** (~5,000 個左右)
- 過濾掉 DLC、擴展內容、虛擬貨幣等
- **預期效果：** 執行時間減半 ⚡⚡

### 設計決策

#### 1. 過濾開關設計
**決定：** 添加可選參數 `FILTER_DLC = 1/0`
- **1（預設）**：只統計遊戲本體，性能優化模式
- **0**：統計所有產品，完整模式（保留原有行為）
- **CLI 參數：** `--filter-dlc {0,1}` （0=統計所有，1=只統計遊戲本體）
- **理由：** 用戶需求多樣性、向後相容、靈活性、測試便利

**實現步驟：**

**識別技術指標：**

### 問題 1：批量查詢 API 的 URL 過長導致超時（優先度 🔴 高）

**症狀：**
- 執行程式時，`fetch_products_by_ids()` 返回 **408 Request Timeout** 錯誤
- 特別是在批量查詢 25 個產品 ID 時發生

**根本原因：**
- [scraper.py 第 312 行](scraper.py#L312)：使用 **GET 請求**，將所有 ID 拼接成 URL 參數
- 範例：`productIds=ID1,ID2,ID3,...ID25` 導致 URL 過長
- Xbox API 伺服器對 URL 長度有限制，超過時返回 408

**臨時修復（已實施）：**
- ✅ 將 `batch_size` 從 25 改為 5（2026-04-09 22:30）
- ⚠️ **測試結果：** 報表仍然顯示台灣商店全部遊戲為下架，與實際狀況不符
- **結論：** batch_size 減小無法解決根本問題，408 超時可能仍在發生或存在其他隱藏的異常

**長期解決方案（待實施 - 2026-04-10）：**
- [ ] 改用 **POST 請求** 而非 GET（這是根本解決方案）
- [ ] POST body 中傳遞 ID 列表，不受 URL 長度限制
- [ ] 恢復 `batch_size = 25` 的效率
- [ ] 實施後需驗證報表是否正確顯示台灣商店可購買遊戲

### 問題 2：異常處理隱藏了查詢失敗，導致遊戲被誤判為已下架（優先度 🔴 高）

**症狀：**

**根本原因鏈：**

## 🎓 設計決策記錄

### 為什麼 FILTER_DLC 使用 1/0 而非 True/False？
1. **CLI 兼容性：** argparse 處理整數參數比布林值更直觀。
2. **資料庫存儲：** SQLite 中 `is_base_game` 以 `INTEGER` 存儲，使用 1/0 保持一致性。

### 為什麼過濾開關應該是可選的？
1. **用戶需求多樣性：** 有些用戶可能對 DLC 感興趣（比如獨占 DLC）
2. **向後相容：** 不強制改變現有行為
3. **靈活性：** 允許根據使用場景選擇
4. **測試便利：** 便於比較過濾前後的差異
